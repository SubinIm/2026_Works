# Chrome 확장 프로그램 공통 검증 절차

다운로더와 광고 차단기 등 Chrome 확장 프로그램을 실제 브라우저에서 검증하기 위한 재사용 가이드다. 도구 연결, 확장 내부 메시지, 사용자 UI, 최종 결과를 분리해 기록한다. 이 절차를 읽었다는 이유만으로 다른 프로젝트의 설치·설정 변경·테스트가 수행된 것은 아니다.

## 준비와 범위 합의

1. 프로젝트의 AGENTS.md, README, manifest.json, 테스트 명령과 기존 검증 기록을 읽는다. 다른 작업의 변경은 보존한다.
2. 검증 대상 버전, 설치 폴더, 테스트 URL, 예상 결과, 허용된 변경 범위를 정한다.
3. 개인 Chrome 대신 별도 테스트 프로필을 우선 사용한다. 개인 프로필에는 명시적 승인 없이 연결하지 않는다.
4. 확장 설치 등 도구가 실행 직전 확인을 요구하는 작업은 확인 후 실행한다. 접근 거부를 다른 도구나 임시 복사로 우회하지 않는다.
5. 테스트 파일 생성과 설정 변경 내역을 기록한다. 기존 다운로드·규칙·기록을 삭제하지 않는다.

## DevTools MCP 설정과 연결

이번 환경에서 확인한 조합은 Chrome 153, Node 24, Chrome DevTools MCP 1.10.1이다. 다른 컴퓨터에서는 실제 버전과 지원 옵션을 다시 확인한다. MCP는 개발 도구이며 배포할 확장의 런타임 의존성으로 넣지 않는다.

설정 원칙:

- 검증한 MCP 버전을 고정한다.
- `--isolated`: 임시 테스트 프로필 사용. 재시작 후 확장·설정이 없어질 수 있다.
- `--categoryExtensions`: 확장 관련 도구 활성화.
- `--workspace <저장소 절대 경로>`: 설치할 확장 폴더를 포함하는 최소 작업 경로만 허용.
- `--no-usage-statistics`, `--no-performance-crux`: 사용 통계와 CrUX 전송 비활성화.
- `--redactNetworkHeaders`: 민감 헤더 가리기. URL 경로·쿼리의 토큰까지 모두 가려진다고 가정하지 않는다.
- `CHROME_DEVTOOLS_MCP_NO_UPDATE_CHECKS=1`: 자동 업데이트 확인 비활성화.
- 개인 프로필 자동 연결과 무제한 파일 경로 허용은 기본으로 사용하지 않는다.

설정 변경 후 MCP를 다시 연결한다. 현재 도구에 반영되지 않으면 Codex를 재시작하고 이 가이드부터 재개한다. 도구 목록 응답은 서버 초기화 확인일 뿐 브라우저 연결 증거가 아니다.

1. `list_pages`로 실제 Chrome 응답을 확인한다.
2. `list_extensions`로 설치 여부·ID·버전을 확인한다.
3. 미설치라면 승인된 manifest.json 포함 폴더를 `install_extension`에 전달한다.
4. 설치 후 목록을 다시 읽고 service worker 존재를 확인한다.
5. 빌드가 필요한 프로젝트는 산출물을 로드한다. 소스 수정만으로 기존 탭의 콘텐츠 스크립트가 교체됐다고 판단하지 않는다.

## 로컬 페이지 준비

서버 프로세스가 살아 있는지 확인하고 브라우저로 페이지를 연다. `ERR_CONNECTION_REFUSED`는 먼저 서버 실행·포트·주소를 점검한다. 확장 결함으로 바로 분류하지 않는다.

이 저장소의 실행 예시:

```powershell
# 저장소 루트에서, 실제 사용 가능한 Python 실행 파일로 실행
python fixtures/server.py --port 8765 --directory fixtures

# 광고 차단기 fixture는 별도 포트
node adblocker/fixtures/server.mjs 8766
```

다운로더: `http://127.0.0.1:8765/player/`

광고 차단기: `http://127.0.0.1:8766/`

Python의 WindowsApps 실행 별칭이 실패하면 실제 설치된 python.exe를 확인한다. 서버 종료나 앱 재시작 후 서버가 유지된다고 가정하지 않는다. 서버가 출력한 주소와 브라우저 응답을 함께 확인한다.

## 공통 검사 순서

1. 확장 사용 전 또는 기능 OFF 상태의 화면·네트워크를 기준으로 기록한다.
2. 최신 snapshot을 읽고 실제 UI에서 동작을 수행한다. 내부 상태만 변경한 시험과 구분한다.
3. 기능 ON 상태에서 같은 입력·페이지로 비교한다. 캐시·네트워크·다른 확장 영향을 기록한다.
4. 콘솔 오류, network 응답, DOM 및 service worker 상태 중 해당 주장에 필요한 증거만 수집한다.
5. 실패하면 최소 재현 입력을 만들고 원인을 확인한다. 수정 요청 범위 안에서만 수정하고 같은 조건으로 재시험한다.
6. 확장 reload 후 페이지도 다시 로드한다. SPA 이동, 동적 DOM, iframe, 다중 탭을 별도로 검사한다.
7. 팝업 닫기, 다시 열기, service worker 종료·재시작을 각각 검사한다. 디버거 연결 상태를 기록하고 연결을 해제한 조건도 확인한다.

`evaluate_script`로 실제 `chrome.runtime.sendMessage`를 호출한 결과는 **메시지 통합 검사**다. 버튼 클릭, 입력값 유지, 비활성화 표시, 사이드바, 팝업 수명주기의 통과 증거로 대체하지 않는다. 확장 페이지를 일반 탭으로 연 경우도 실제 팝업 검사와 구분한다.

## 다운로더 검사 항목

| 단계 | 통과 기준 |
| --- | --- |
| 연결 | 실제 확장 ID와 Native Host allowed_origins 일치, health 응답 정상 |
| 실행 파일 | FFmpeg와 FFprobe 경로·실제 실행 확인. 새 프로필의 빈 설정 주의 |
| 탐지 | MP4·HLS·DASH 탐지, ts·m4s는 독립 다운로드 카드가 아님 |
| blob | Probe·Download·세션 체크 비활성화, 안내 표시, Host 전송 차단 |
| 일괄 Probe | 음성 없는 후보 뒤에 영상과 음성 있는 후보를 배치하고 끝까지 확인하는지 검사 |
| 선택 | 전체 검사의 확인 수·실패 수·선택한 후보와 실제 Probe 스트림 결과 일치 |
| 다운로드 | UI 클릭 검사와 메시지 호출 검사를 각각 기록, 기존 파일 덮어쓰기 방지 |
| 출력 | FFprobe video/audio와 duration 확인, FFmpeg null decode 오류 없음 |
| 수명주기 | 팝업 종료 후 지속, worker 재시작 복구, 취소 후 자식 프로세스·partial 정책 확인 |
| 인증과 DRM | 쿠키 opt-in, 토큰 redaction, 만료 URL, AES-128과 SAMPLE-AES·DRM UUID 구분 |

입력 Probe 생략은 사용자 선택으로 유지한다. 임의의 다른 영상에서 오디오를 합치거나 무음 허용을 자동으로 켜서 실패를 숨기지 않는다.

## 광고 차단기 검사 항목

대상 프로젝트의 실제 지원 범위를 먼저 읽는다. 이 저장소의 `adblocker`는 배너 차단·수동 숨김·이동과 선택형 일반 영상 광고 요청 차단, 실험적인 YouTube 광고 메타데이터 제거·건너뛰기를 지원한다. 모든 영상 내부 광고 제거와 모든 사이트 지원을 보장하지 않는다.

| 항목 | 검사 방법과 통과 기준 |
| --- | --- |
| 네트워크 차단 | 동일 요청을 OFF와 ON에서 비교하고 적용 규칙 증거와 대조. 단순 네트워크 실패를 차단 성공으로 세지 않음 |
| CSS 숨김 | 광고 표본만 숨겨지고 기사·검색·영상·일반 댓글은 유지 |
| 화면 밖 이동 | 이동 전후 위치와 원복 확인. 요청이 계속되면 네트워크 차단 성공이라고 표현하지 않음 |
| 예외 | 전체 OFF·현재 사이트 OFF·허용 규칙이 의도한 우선순위로 동작 |
| 공개 필터 | 활성 규칙 묶음·버전·로드 오류 확인. 전체 규칙 수와 현재 페이지 차단 수를 구분 |
| 수동 선택 | 상위·하위 영역, 미리보기, 취소, 저장, 실행 취소 및 재방문 후 복원 |
| iframe | 동일 출처·다른 출처·빈 프레임, 프레임 교체 시 이전 선택을 새 요소에 적용하지 않음 |
| 동적 페이지 | 광고 재삽입·SPA 이동·임의 클래스 변경 시 과잉 숨김이나 누적 관찰자 오류 없음 |
| 선택형 영상 광고 | 초기·추가 응답의 광고 데이터 제거 및 광고 상태의 건너뛰기를 OFF/ON 비교. 본 영상·자막·오류·속도·음량 보존과 해제 후 재로드 복원. 모의 응답의 성공을 실제 광고 재생 성공으로 집계하지 않음 |
| 백업 | 내보내기·미리보기·중복 가져오기·손상 JSON 거부. 기존 사용자 규칙 보존 |
| UI | 팝업·사이드바의 사이트 표시, 좁은 폭, 탭 전환, 버튼 기능과 상태 일치 |
| 성능 | 같은 페이지·조건으로 확장 OFF와 ON을 반복 비교. 단일 실행 수치를 일반화하지 않음 |

다른 광고 차단 확장이 없는 테스트 프로필에서 수행한다. 이 프로젝트의 공개 필터에는 localhost 등 일부 주소의 범용 CSS 예외가 있으므로 로컬 fixture 결과만으로 공개 CSS 필터를 판정하지 않는다. 필요한 추가 표본은 지원 대상과 예외를 확인한 뒤 선정한다. 실제 사이트 검증 범위는 사용자가 지정한 페이지로 제한하며 유료벽·인증·보안 경고를 우회하지 않는다.

기존 자동 검사는 `adblocker` 폴더에서 `node --test tests/*.test.mjs`로 실행할 수 있다. 필요한 브라우저 등 의존성이 없어 실행되지 않은 검사는 NOT RUN 또는 BLOCKED로 기록한다. 상세 수동 항목은 [광고 차단기 수동 검사](../adblocker/MANUAL_TEST.md)와 함께 사용한다.

## 결과 기록 양식

| ID | 대상과 버전 | 검증 경로 | 입력과 재현 절차 | 기대 결과 | 실제 증거 | 판정 |
| --- | --- | --- | --- | --- | --- | --- |
| 예시 | 확장 이름과 버전 | UI 또는 메시지 또는 단위 | URL과 클릭 또는 명령 | 구체적 조건 | 오류·요청·파일 검사 결과 | NOT RUN |

- PASS: 기대 조건을 실제로 확인함.
- FAIL: 실행했으나 기대 조건 불충족. 원인, 수정 파일, 수정 후 재시험 결과를 추가한다.
- BLOCKED: 권한·의존성·연결 등으로 실행 불가. 정확한 차단 이유와 필요한 조치를 기록한다.
- NOT RUN: 아직 실행하지 않음. skip을 PASS로 바꾸지 않는다.

날짜, Chrome·MCP·확장 버전, 프로필 종류, fixture 버전, 변경한 설정과 생성 파일을 기록한다. Cookie·Authorization·서명 URL 원문은 보고서에 남기지 않는다. 테스트가 만든 자원만 정리하고 사용자 데이터 삭제는 별도 승인 없이 수행하지 않는다.

## 이번 다운로더 검증에서 확보한 범위

2026-10-06, 확장 0.2.6과 Host 0.2.2:

- PASS: Chrome 연결, 확장 설치, Host 연결, FFmpeg 경로 적용 후 health 정상.
- PASS: HLS·DASH 브라우저 재생, MP4/HLS/DASH 후보 탐지, 세그먼트 독립 후보 제외.
- PASS: 실제 확장 메시지 경로의 전체 Probe에서 3개 모두 영상·음성 확인.
- PASS: 메시지 경로 다운로드 3개 완료. 출력 H.264/AAC, MP4 8.000초·HLS/DASH 8.021333초, decode 종료 코드 0.
- 시험 입력 오류: 잘못된 `overwrite: rename`을 Host가 거부함. 실제 허용 값 `number`로 고친 후 재시험 성공. 제품 결함으로 집계하지 않음.
- NOT RUN: 실제 팝업 버튼 다운로드, 팝업 종료·worker 재시작·취소 수명주기, 실제 YouTube 음성 후보 선택 재현.

이 결과를 광고 차단기나 다른 버전의 PASS로 전용하지 않는다.
