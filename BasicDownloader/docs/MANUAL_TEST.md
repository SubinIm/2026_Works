# 수동 acceptance test

1. `scripts\verify-environment.ps1`로 Node, Python, FFmpeg/FFprobe를 확인한다.
2. `scripts\build-extension.ps1`을 실행한다.
3. `chrome://extensions`에서 개발자 모드를 켜고 `extension\dist`를 unpacked로 로드한다.
4. 표시된 32자 extension ID를 기록한다.
5. `scripts\build-host.ps1`을 실행하고 `scripts\install-host.ps1 -ExtensionId <ID>`로 등록한다.
6. Chrome을 다시 시작하고 popup에서 Host/FFmpeg 정상 상태를 확인한다.
7. `scripts\start-fixture-server.ps1`을 실행하고 출력된 test page를 연다. PATH에 도구가 없다면 `-FFmpegPath 'C:\path\ffmpeg.exe' -Python 'C:\path\python.exe'`를 지정한다.
8. MP4를 재생하고 MP4 후보가 하나만 나타나는지 확인한다.
9. HLS/DASH 링크를 요청하고 `.m3u8`/`.mpd` 후보가 나타나며 `.ts`/`.m4s` 카드는 없는지 확인한다.
10. Probe에서 video/audio stream과 duration을 확인한다.
11. Auto로 HLS와 DASH를 다운로드하고 진행 이벤트와 최종 경로를 확인한다.
12. 결과에 `ffprobe -v error -show_streams <file>`를 실행해 video/audio stream을 확인한다.
13. 긴 작업을 취소해 상태와 partial 정리, 작업 관리자에서 orphan FFmpeg가 없는지 확인한다.
14. Chrome 재시작과 service worker 중지/재시작 뒤 후보와 설정 동작을 확인한다.
15. `scripts\uninstall-host.ps1`로 등록을 제거한다.

## Chrome 수명주기 확인

1. player의 slow HLS를 재생하고 popup에서 Download를 시작한다.
2. popup을 닫은 뒤 작업 관리자에서 `ffmpeg.exe`가 실행 중인지 확인한다.
3. popup을 다시 열어 같은 job ID와 `running` 상태가 표시되는지 확인한다.
4. `chrome://extensions` → 확장 → 서비스 워커 검사에서 worker를 종료한 뒤 popup을 다시 연다.
5. Host 상태가 재연결되고 `list_jobs`로 같은 job이 나타나는지 확인한다.
6. 작업 중 `stream_host.exe`를 작업 관리자에서 종료하고 popup에서 단절 오류를 확인한다. 다음 재연결 후 registry의 job 상태가 복구되는지 확인한다.
7. 취소를 누른 직후 PowerShell에서 `Get-Process ffmpeg -ErrorAction SilentlyContinue`를 실행해 해당 PID가 없는지 확인한다.
8. 기본 partial 정책에서는 `*.partial.*`가 없어야 하고, 보존 옵션을 켠 실패/취소 작업에서는 partial 파일이 있어야 한다.

## 인증·저장소 확인

1. Referer manifest의 Probe가 성공하는지 확인한다.
2. Cookie 설정 전 Cookie manifest가 403이고, `fixture Cookie 설정` 후에도 popup의 `현재 사이트 세션 포함`을 끄면 실패하는지 확인한다.
3. 체크박스를 켰을 때만 Cookie manifest Probe가 성공해야 한다.
4. 만료 signed manifest는 403/만료 가능성으로 표시되고 token 값은 오류 상세에 나타나지 않아야 한다.
5. service worker 콘솔에서 `await chrome.storage.local.get(null)`과 `await chrome.storage.session.get(null)`을 실행해 Cookie와 token 값이 없는지 확인한다.

Chrome과 FFmpeg가 필요한 항목은 이 저장소의 자동 테스트만으로 검증됐다고 간주하지 않는다.

## 팝업 갱신 회귀 확인 (2026-10-05)

1. 다시 빌드한 `extension\dist`를 Chrome 확장 관리 화면에서 새로고침한다. 로컬 player에서 direct MP4와 HLS/DASH를 재생한 뒤 popup을 연다.
2. HTTP(S) 후보가 blob 카드보다 앞에 나타나는지 확인한다. blob 카드의 Probe·Download·세션 체크박스는 계속 비활성화되어야 한다.
3. HTTP(S) 카드의 Download를 눌러 옵션을 연다. 파일명을 수정하고 세션 선택을 바꾼 뒤 새로고침을 누른다. 옵션, 파일명, 선택값이 유지되고 시작 버튼이 정상 동작해야 한다.
4. Probe 결과와 실패 상세는 기본적으로 접혀 있어야 한다. 기술 상세를 연 뒤 후보가 갱신돼도 펼친 상태가 유지되어야 한다.
5. 정지된 direct MP4 페이지에서 10초 이상 기다린다. DOM 재탐지만으로 네트워크 요청 횟수가 늘지 않아야 한다. 실제 새 요청이 발생하는 HLS live 갱신은 증가할 수 있다.
6. slow HLS 작업 중 popup을 닫았다 다시 연다. 상단 작업 목록이 새로고침 버튼 없이 진행 상태에서 완료 상태로 바뀌어야 한다.
7. Host 연결이 끊기면 HTTP(S) 버튼도 비활성화되어야 한다. 자동 재연결 또는 새로고침 후 health가 성공하면 HTTP(S) 버튼은 활성화되고 blob 버튼은 계속 비활성화되어야 한다.

위 항목의 합성 DOM/Native Port 테스트는 자동 실행하지만, 실제 Chrome UI 결과는 별도 기록한다. 2026-10-05 실행에서는 브라우저 도구가 열린 로컬 fixture URL 접근을 정책상 거부하여 실제 UI 검증은 BLOCKED다.

## 0.1.2 진행률·음성 확인

0.1.2 Native Host를 별도로 빌드한 경로는 `native-host\dist\0.1.2\stream_host.exe`다. 기존 등록을 이 실행파일로 갱신하려면 저장소 루트에서 아래 명령을 실행한다. 기존 작업을 강제 종료하거나 FFmpeg 설정을 변경하지 않는다.

```powershell
.\scripts\install-host.ps1 -ExtensionId jpahdpgemdlibedhcodgolicnaieomoh -ExecutablePath '.\native-host\dist\0.1.2\stream_host.exe'
```

1. 실행 중 다운로드가 끝난 뒤 Chrome의 `chrome://extensions`에서 Personal Stream Downloader 새로고침을 누른다. 확장 버전은 **0.1.2**, popup 상단은 **Host v0.1.2 · FFmpeg 정상**이어야 한다. 영상 페이지도 새로고침한다. 저장한 FFmpeg 경로는 유지된다.
2. 로컬 player의 **분리 A/V HLS 재생**을 누른다. 이 master의 Probe 결과에 영상·음성이 각각 1개 이상 표시되어야 한다. `MASTER 추정`만으로 음성 포함 여부를 판단하지 않는다.
3. 같은 후보에서 Probe를 눌러 길이 0:08을 확인하고 Download를 시작한다. 작업 목록에 확인 → 다운로드 → 검증 → 완료가 표시되어야 한다. 전체 길이와 출처가 표시되고, 첫 진행/속도 정보가 도착하면 퍼센트·저장량·배속·예상 남은 시간이 표시되어야 한다. 완료 전에는 100%가 되어서는 안 된다. 짧은 fixture는 매우 빨리 완료될 수 있으므로 진행 확인에는 slow HLS도 사용한다.
4. 영상 전용 child `generated/separate-video.m3u8`의 기본 다운로드는 음성 누락 안내와 함께 실패해야 한다. **영상만 저장(무음 허용)**을 직접 체크한 경우에만 경고와 함께 완료해야 한다.
5. 명시 확인된 무제한 live는 종료 시점이 정해지지 않았다는 설명과 처리 시간/저장량을 보여야 한다. 길이 정보가 아직 도착하지 않은 경우와 Probe에서도 길이를 확인하지 못한 경우의 설명은 달라야 한다. VOD에서 Probe로 길이를 확인했다면 일반적인 '전체 길이를 알 수 없음' 안내가 나오면 안 된다.
6. popup을 닫았다 열어도 작업의 단계·진행 정보가 유지되어야 한다. 확인 단계와 다운로드 단계 모두 취소 가능해야 한다.

위 Chrome 화면 검증과 실제 YouTube의 올바른 원본 후보 선택은 아직 별도로 수행해야 한다. 음성 없는 파일은 재생 설정만으로 소리가 생기지 않으며, 음성이 포함된 원본에서 다시 다운로드해야 한다.

## 0.2.0 다운로드 관리자 최종 화면 확인

검증한 Host 등록은 `native-host\dist\0.2.0\stream_host.exe`로 갱신되어 있다. 진행 중인 다운로드가 끝난 뒤 Chrome 확장 관리에서 확장을 새로고침하고, 사용하는 영상 탭도 새로고침한다. 새 sidePanel/contextMenus/notifications 권한에 대한 Chrome 확인이 나오면 내용을 확인한다. 알림 자체는 설정에서 켜기 전까지 발생하지 않는다.

1. 팝업 상단 **Host v0.2.0 · FFmpeg 정상**을 확인한다. 기존 파일명/FFmpeg 경로 설정을 확인한다.
2. HTTP(S) 후보의 Download 옵션에서 **영상 제목을 파일명으로 사용**을 켠다. 제목 기반 파일명이 들어가야 한다. 직접 편집하면 체크가 해제되고 후보가 갱신돼도 이름이 유지되어야 한다. 다시 체크하면 제목으로 복원한다.
3. poster/대표 이미지가 있는 후보는 출처와 썸네일이 나와야 한다. query URL/CORS 차단/이미지 없음은 기본 표시로 대체되어야 한다. Probe 후 해상도·영상/음성·길이 배지를 확인한다.
4. 같은 페이지 후보 묶기를 켜고 펼침/접힘을 바꾼다. 서로 다른 후보가 하나의 원본이라고 단정하지 않아야 한다.
5. 로컬 fixture를 완료한 뒤 팝업을 닫고 다시 연다. 완료 행의 **재생**은 Windows 기본 플레이어, **폴더에서 선택**은 Explorer에서 정확한 파일 선택, **경로 복사**는 해당 출력 경로여야 한다. 실행 앱이 없거나 파일을 이동한 경우 안전한 오류 안내가 나와야 한다.
6. 완료 행 체크박스·작업 상세를 선택한 상태에서 다른 다운로드가 진행되게 한다. 진행률 갱신에도 선택/상세가 유지되어야 하며, 진행 막대는 드래그되지 않아야 한다.
7. 같은 완료 원본을 다시 다운로드하면 기존 파일 재생/탐색/새로 다운로드 선택창이 나와야 한다. **새로 다운로드**를 명시적으로 선택하기 전 새 작업이 시작되면 안 된다.
8. 완료/실패/취소/DRM 실패만 선택해 목록에서 제거한다. 실제 영상·partial 파일은 유지되고, 팝업/Host 재연결 뒤에도 기록이 다시 나타나지 않아야 한다. 진행 중 항목은 선택 제거할 수 없어야 한다.
9. 목록 접기·전체/진행 중/완료/실패 필터를 확인한다. 항목 우클릭과 `⋯` 메뉴, 키보드 Tab/Shift+F10/Escape로 동일 명령에 접근한다.
10. **사이드바로 보기**를 누르고 다른 영상 탭으로 이동하면 그 탭의 후보로 바뀌어야 한다. 팝업과 사이드바는 같은 작업 상태를 공유한다. 기본 보기 선택은 설정에서 바꾸고 유지되는지 확인한다.
11. 웹페이지/영상/링크 우클릭의 후보 보기와 사이드바 열기를 확인한다. blob 요소에서도 다운로드를 바로 실행하거나 Cookie를 자동 전달하면 안 된다.
12. 설정에서 `{title} [{quality}] {date}` 형식을 저장한다. 완료 알림을 켠 뒤 로컬 fixture를 다운로드하여 알림이 1회 발생하는지 확인한다. 기본 꺼짐에서는 발생하지 않고 알림에 제목/URL이 나오지 않아야 한다.

이 절은 실제 Chrome/Windows UI에서 남아 있는 확인 절차다. 자동 회귀 시험에서 DOM/API/OS 호출을 검증한 것과 실제 화면 실행을 구분한다.

## 0.2.8 첫 클릭 다운로드와 간결한 도움말

1. 진행 중 다운로드가 끝난 뒤 `chrome://extensions`에서 확장을 새로고침하고 0.2.8을 확인한다. Host 재등록은 필요 없다.
2. 로컬 서버에서 `/player/acceptance-028.html?run=새로운시험이름`을 연다. 확장 새로고침 후 전체 후보 확인·확인 후 자동 다운로드를 체크한다. 다른 후보를 펼쳐 `separate-video.m3u8?acceptance=...` 카드의 Download를 한 번 누른다. 무음 후보의 실패 작업을 먼저 만들지 않고 음성 포함 `separate-av.m3u8`를 선택해 완료해야 한다. 이미 받은 원본은 기존 중복 확인을 보여주는 것이 정상이다.
3. 자동 다운로드 체크를 끄면 Download는 기존 파일명 옵션을 열고 시작 전까지 저장하지 않아야 한다. 시작 전 Probe를 끄면 자동 후보 Probe를 강제하지 않아야 한다. 로그인 쿠키·음성만 저장·무음 허용은 선택한 카드에만 적용되어야 한다.
4. 옵션 행 또는 `?`에 커서를 올리거나 Tab으로 도움말 버튼을 선택하면 상세 설명이 표시되어야 한다. `?` 클릭으로 고정하고 Esc로 닫는다. 설명이 펼침/Download 등 아래 버튼의 클릭을 가로막으면 실패다. 360px 사이드바에서도 가로 잘림이 없어야 한다.
5. 주소·탐지 정보와 SABR/blob 상세는 기본 접힘이어야 하며 눌러서 펼칠 수 있어야 한다. 오류·진행 상태와 blob 버튼 비활성화는 유지되어야 한다.

## 0.2.5 전체 Probe와 자동 다운로드 옵션

확장 새로고침 후 0.2.5를 확인한다. 사이드바에서 'Probe 한 번으로 전체 후보 확인'을 켜고 카드의 Probe 또는 전체 후보 Probe 버튼을 누른다. 첫 AV 성공 이후에도 남은 후보를 확인하고 가장 적합한 AV 카드가 대표로 표시되어야 한다. 자동 다운로드 옵션은 기본 꺼짐이며 꺼진 상태에서 다운로드가 시작되면 안 된다. 옵션을 켜고 다시 실행하면 적합한 1개에만 요청하며 중복 기록이 있으면 확인 UI를 유지해야 한다. 창 닫기 전 자동 시작 여부를 확인한다. blob만 있을 때는 새로고침의 한계를 설명하는 안내가 나오고, 기존 HTTP(S) 후보는 목록 새로고침만으로 없어지면 안 된다.

## 0.2.4 영상+음성 찾기 / 음성만 저장

확장 0.2.4 / Host 0.2.2 연결 후 '영상+음성 후보 찾기'를 한 번 누른다. 오류·무음 후보를 건너뛰고 성공 후보를 찾으면 해당 카드가 대표로 올라가며 파일명 옵션이 열린다. 시작 버튼을 누르기 전 다운로드가 시작되면 안 된다. 최대 20개 또는 후보 끝까지 찾지 못하면 실패 개수/제한 안내가 보여야 한다. 쿠키는 보내지 않으므로 인증이 필요한 후보는 기존 수동 Probe를 사용한다.

'음성만 저장'을 켜면 '영상만 저장(무음 허용)'은 해제/비활성화되어야 한다. MP4/HLS/DASH에서 입력 Probe 켬/끔 각각 다운로드하고 출력에 음성만 있는지 확인한다. 출력은 MP4 또는 MKV 컨테이너이며 MP3 변환이 아니다. 완료 파일 재생/폴더 선택은 기존과 동일하게 작동해야 한다. 이전 Host는 이 선택을 비활성화하고 갱신 안내를 표시해야 한다.

## 0.2.3 다운로드 시작 전 Probe 선택

확장 0.2.3과 Host 0.2.1을 사용한다. 후보 카드의 '다운로드 시작 전 Probe (선택)'는 기본 체크다. 체크를 해제하고 Download → 시작하면 입력 FFprobe 없이 다운로드가 진행되어야 한다. 이 설정은 탐지 시 자동 Probe 및 별도 Probe 버튼과 독립적이다. 모든 입력 Probe를 피하려면 설정의 탐지 시 자동 Probe도 꺼 둔다. DRM 검사 및 완료 전 출력 검증은 유지된다. 길이 힌트가 없으면 Probe 생략 안내와 처리 시간/저장량만 표시한다. 영상만 있는 파일은 무음 허용을 별도로 선택하지 않으면 완료 처리되지 않아야 한다. 구형 Host에서는 생략 체크가 비활성화되고 갱신 안내가 보여야 한다.
