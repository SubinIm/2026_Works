# Basic Banner Blocker

개발 검증에는 [Chrome 확장 프로그램 공통 검증 절차](../docs/CHROME_EXTENSION_ACCEPTANCE.md)를 사용합니다. DevTools MCP 설정, 실제 UI와 메시지 검사 구분, 광고 차단 OFF/ON 비교 및 결과 기록 양식을 포함합니다.

개인 사용을 위한 Chrome Manifest V3 광고 차단 확장 프로그램입니다. 기본 배너 규칙에 EasyList와 한국어 공개 필터를 더하고, 남아 있는 광고는 우클릭으로 선택해 사이트별로 숨기거나 화면 밖으로 이동시킵니다. 분석·추적 차단, 일부 영상 광고 요청 차단, 실험적인 YouTube 영상 광고 차단, Canvas·오디오 지문 보호, 광고 API 제한과 GPC 신호를 독립적으로 선택할 수 있습니다. 모든 영상 서비스와 광고 방식을 지원하지는 않습니다.

기존 Personal Stream Downloader와 별개로 설치합니다. 확장 프로그램 사용에는 Node.js, Python, FFmpeg 또는 빌드 작업이 필요하지 않습니다.

Chrome 128 이상이 필요합니다. 공개 목록의 응답 헤더 조건이 사용하는 API의 최소 버전에 맞췄습니다. [Chrome DNR 문서](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest#property-RuleCondition-responseHeaders)

## Chrome에 설치

1. 주소창에 `chrome://extensions`를 입력합니다.
2. 오른쪽 위 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다**를 누릅니다.
4. 이 `adblocker` 폴더를 선택합니다. `manifest.json`이 바로 들어 있는 폴더입니다.
5. 기존에 열려 있던 웹페이지를 새로고침합니다. Chrome 도구 모음의 확장 프로그램 메뉴에서 **Basic Banner Blocker**를 고정하면 설정을 쉽게 열 수 있습니다.

현재 작업 폴더에서의 설치 위치:

```text
C:\Users\Acrob\MATLAB Drive\2026_Works\BasicDownloader\adblocker
```

업데이트한 파일을 적용할 때는 확장 관리 화면의 새로고침 버튼을 누른 뒤 웹페이지도 새로고침합니다.

### 0.10.2 업데이트 적용

`chrome://extensions`에서 **Basic Banner Blocker의 새로고침(↻)**을 누른 뒤, 열려 있던 웹페이지도 **Ctrl+Shift+R**로 다시 불러옵니다. 버전이 **0.10.2**인지 확인합니다. 확장 파일 수정만으로 기존 탭의 콘텐츠 스크립트가 교체되지는 않습니다. 기존에 저장한 숨김·이동 규칙과 사이트 예외는 유지됩니다.

0.10.2는 YouTube 광고 자동 건너뛰기를 보완합니다. 화면 크기 변화, 탭이 다시 보이는 시점과 영상 재생·진행 이벤트에서도 버튼을 확인합니다. CSS 변화로 플레이어가 다시 보이지만 DOM 속성은 바뀌지 않는 경우의 누락을 재현하고 수정했습니다.

로그인된 실제 플레이어에서 새 건너뛰기 UI가 프로그램 클릭을 거부하는 것을 확인했습니다. 이 UI에는 반복 클릭을 보내지 않습니다. 활성 버튼·명시적 광고 상태·탐색 불가 광고 진행 정보와 본 영상보다 별도의 길이를 가진 미디어가 모두 일치하고 광고 마지막 구간이 탐색 가능할 때만 그 광고 구간의 끝으로 이동합니다. 이 종료 방식은 URL의 영상 ID와 초기 본 영상 정보를 대조할 수 있는 일반 시청 페이지에서만 실행합니다. 본 영상과 합쳐진 스트림, 오래된 SPA 재생 정보와 모호한 상태에서는 동작하지 않습니다. 건너뛰기 대기 시간이나 건너뛰기 불가능 광고까지 없애지는 않습니다.

전체 자동 검사 **144개 통과, 실패·생략 0개**. 로그인된 실사이트에서 광고 구간 종료 후 본 영상 복귀와 약 102초 후의 정상 재생을 확인했습니다. 이 실사이트 종료 검사는 개발 도구로 광고 위치만 조정한 검사이며 자동 확장 실행 결과와 구분합니다. 사용자가 0.10.2를 다시 로드한 뒤 해당 프로필에 적용된 스크립트가 현재 소스와 같고 본 영상이 1분 이상 재생되는 것도 확인했습니다. 광고가 없는 표본만으로 실제 자동 건너뛰기 성공률을 주장하지 않습니다.

0.10.1은 일부 YouTube 영상이 약 59초 뒤 또는 이후 구간 탐색 시 재생 오류가 나는 증상에 대응합니다. SABR 재생 주소를 포함한 데이터에서는 광고·재생 협상 정보를 통째로 보존하며, 광고에 표시된 건너뛰기 버튼을 자동으로 누르는 기능은 유지합니다. 일반 IMA/VAST 차단에서도 YouTube·YouTube 삽입용 도메인을 제외해 전용 플레이어 동작과 충돌하지 않게 했습니다. 해당 모드에서는 건너뛰기 불가능한 광고가 남을 수 있으며, 재생 안정성을 우선합니다.

다만 이번 실제 검사에서는 수정본뿐 아니라 확장이 허용되지 않는 새 비로그인 세션에서도 같은 긴 재생 오류가 재현됐습니다. 0.10.1이 이 오류를 완전히 해결했다고 주장하지 않습니다. 자동 검사 **142개 통과, 실패·생략 0개**는 응답 보존·차단 범위·기존 기능의 회귀 검증이며 실사이트의 지속 재생 성공과 구분합니다. 로그인 상태와 실제 사용 Chrome에서의 비교가 추가로 필요합니다. 비로그인 사용자에게 공통적인 1분 재생 제한이 있다는 뜻은 아닙니다. [YouTube 공식 재생 오류 안내](https://support.google.com/youtube/answer/3037019?hl=en).

**규칙 관리 · 백업 → 영상 광고 · 지문 보호 → YouTube 영상 광고 차단 (실험)**을 켠 뒤 YouTube 페이지를 새로고침하세요. 새 설치와 기존 설정의 기본값은 꺼짐입니다. 개발 검증용 Chrome에서는 실제 스위치로 켜 두었습니다. 사용자의 다른 Chrome 프로필 설정은 변경하지 않았습니다.

- 초기 `ytInitialPlayerResponse`와 지정한 재생 응답의 `adPlacements`·`adSlots`·`playerAds`를 제거합니다. Fetch·XHR와 추가 페이지 이동을 처리하며 본 영상 주소·자막·재생 오류는 보존합니다. Shorts 목록에서는 `isAd=true`로 명시된 광고 항목만 제거합니다.
- SABR 주소가 있는 재생 응답은 초기·Fetch·XHR 모두 원문과 광고 필드를 보존합니다. 중첩 응답에서도 해당 재생 방식이 발견되면 전체 응답을 보존해 연결된 정보를 일부만 지우지 않습니다. 이 방식에서는 자동 건너뛰기를 사용합니다.
- 광고 상태의 플레이어에 표시된 건너뛰기 버튼을 이용합니다. 기존 UI는 버튼 클릭, 새 UI는 위의 조건으로 확인한 별도 광고 구간 종료를 사용합니다. 일반 영상을 끝으로 강제 이동하거나 음량·재생 속도를 바꾸지 않습니다. 광고 정보 제거를 통과한 건너뛰기 불가능 광고는 남을 수 있습니다.
- HTTPS의 `youtube.com`·`www.youtube.com`·`m.youtube.com` 최상위 문서만 대상으로 하며 일반 IMA 옵션과 독립적입니다. 외부 페이지에 삽입된 YouTube 프레임·Worker·로그인 계정별 모든 실험·서버에서 합친 광고를 지원한다고 보장하지 않습니다. 영상 서버 전체를 차단하지 않으며 인증·재생 불가 안내도 바꾸지 않습니다.
- 전체·사이트 일시 중지가 우선합니다. 켜거나 끈 뒤 새로고침해야 초기 패치가 적용·해제됩니다. 재생 오류나 로딩 문제가 생기면 이 옵션을 끄고 새로고침하세요. 추가 권한·원격 코드·자동 학습은 없습니다.

### 0.9.0의 광고 API · GPC 기능

**규칙 관리 · 백업 → 광고 API · 개인정보 거부 신호**에 두 옵션을 추가했습니다. 둘 다 기본값은 꺼짐이고 독립적이며 전체·사이트 일시 중지가 우선합니다. 적용·해제 후 웹페이지를 새로고침하세요. 새 권한은 추가하지 않았고 Chrome의 전역 개인정보 설정도 변경하지 않습니다.

- **Privacy Sandbox 광고 API 제한:** 문서 응답의 기존 Permissions-Policy를 유지하면서 광고·Private State Token 기능의 빈 허용 목록을 추가합니다. 최상위 문서에서는 Topics·광고 경매·광고 기여 보고 속성·Private State Token 등 지정한 API 노출도 제거합니다. 브라우저가 지원하는 정책은 하위 프레임에 상속되지만 하위 프레임·Worker의 JS API는 직접 제거하지 않습니다. 토큰 기반 인증 등에 문제가 생기면 해당 옵션을 끄거나 사이트 차단을 일시 중지하고 새로고침하세요. 브라우저 전체의 광고 개인정보 설정을 끄는 기능은 아니며 미지원 정책은 브라우저가 무시합니다.
- **개인정보 판매·공유 거부 신호 보내기 (GPC):** 페이지 탐색과 일반 HTTP 요청에 `Sec-GPC: 1`을 보내고 최상위 문서에서 `navigator.globalPrivacyControl=true`를 제공합니다. 서버가 신호를 따르는지는 별개이며 광고·쿠키·동의 창을 자동으로 제거하지 않습니다. 삽입 프레임·Worker의 JS 속성은 변경하지 않아 브라우저 내장 GPC와 동일한 전 범위 구현은 아닙니다. 기존 브라우저의 네이티브 true 신호를 덮어쓰거나 제거하지 않습니다. [GPC 명세](https://w3c.github.io/gpc/), [Chrome DNR](https://developer.chrome.com/docs/extensions/reference/api/declarativeNetRequest), [Permissions Policy 명세](https://w3c.github.io/webappsec-permissions-policy/).

2026-10-06 최종 0.9.0 격리 Chrome에서 모든 선택 보호를 켠 AdBlockBench가 **100점**(Network 23/23, Cosmetic 13/13, API 4/4)을 기록했습니다. 남았던 Sandbox와 Opt-out 두 채점 신호가 통과했습니다. 실제 Edge 확장에서는 GPC 헤더의 서버 도착, 기존 문서 정책 보존, 지원 정책의 하위 프레임 제한과 사이트 일시 중지·전체 OFF·옵션 해제 후 복원을 검사했습니다. Adblock-tester 100점과 스포츠서울 홈·기사 본문 표시도 유지됐습니다. 전체 자동 테스트는 **127개 통과·실패/생략 0개**입니다. 이 점수는 비채점 6개 항목과 모든 실사이트 광고·추적 방식을 포함하지 않습니다. [검증 기록](MANUAL_TEST.md).

0.8.1은 디시인사이드 PC 갤러리의 **화면을 떠다니는 개죽이**를 기본 차단에 포함합니다. 관측한 `styleGaejuki` 전용 스타일시트를 비활성화해 배경 투명화·이동 효과를 해제하고, `gaejukimg`의 전용 이미지와 같은 기능이 만든 빈 전체 화면 클릭 방해 레이어를 숨깁니다. 이미지 주소·직접 자식 구조·전용 스타일과 정확한 `gall.dcinside.com` 출처를 함께 확인합니다. 일반 본문 이미지나 다른 사이트의 고정 메뉴·대화상자를 일괄 제거하지 않습니다. 전체·사이트 차단을 끄면 원래 표시와 스타일을 복원하며, 요소 재삽입·스타일 재설정에도 다시 적용합니다. 새 권한과 옵션은 추가하지 않았습니다. 다른 방해 요소는 기존 **우클릭 → 이 요소 숨기기**로 선택할 수 있습니다.

녹색 방패·체크 아이콘을 툴바, 확장 관리, 설정 탭, 팝업과 사이드바에 적용했습니다. 편집 가능한 원본은 `icons/mark.svg`, Chrome용 PNG는 16·32·48·128px입니다. 개발용 재생성 명령은 `node tools/build-icons.mjs`이며 개발 환경의 Playwright가 필요합니다. 확장 사용에는 빌드 도구가 필요하지 않습니다.

**확장 아이콘 → 사이드바에서 열기**를 누르면 설정을 Chrome 사이드바에 유지할 수 있습니다. 전체·현재 사이트 차단, 숨기기·이동시키기, 저장한 규칙 복원과 관리 화면 열기를 지원합니다. 같은 창에서 탭을 바꾸거나 페이지를 이동하면 현재 사이트로 갱신하며, 다른 창의 탭 변경은 따라가지 않습니다. 요소 선택을 시작해도 사이드바는 닫히지 않습니다. 사이드바 폭에 맞춰 화면이 줄어들고 긴 규칙 목록은 아래로 스크롤할 수 있습니다. 기존 아이콘 팝업도 유지합니다.

사이드바 표시에 [Chrome Side Panel API](https://developer.chrome.com/docs/extensions/reference/api/sidePanel)와 `sidePanel` 권한을 사용합니다. `sidepanel.html`은 팝업과 같은 UI 로직을 사용하며 백그라운드는 이 확장의 정확한 페이지 주소에만 설정 권한을 부여합니다.

0.4.1에서는 스포츠서울 기사 광고의 ID·클래스가 새로고침마다 바뀌는 경우를 보완했습니다. 관측한 바깥 광고 영역은 고정된 부모 영역과 빈 주소 iframe의 크기 조합으로 저장하며, 여러 영역이 일치하면 임의로 모두 이동시키지 않습니다. 긴 임의 영숫자 이름도 고정 선택자 후보에서 제외합니다. 기존에 임의 이름으로 저장한 규칙은 자동으로 다른 요소에 연결하지 않으므로, 해당 규칙을 복원하고 다시 선택해 저장하세요. 광고 내부 내용 자체가 매번 바뀌는 경우에는 **팝업 → 요소 이동시키기**로 **iframe 상자 전체**를 선택하는 편이 안정적입니다. 이 수정이 광고 차단 감지 회피를 보장하지는 않습니다.

우클릭 메뉴에 **이 요소 이동시키기…**를 추가했습니다. 선택한 요소를 제거하지 않고 화면 밖으로 옮기는 수동 규칙을 저장합니다. **이동 미리보기 → 저장**으로 적용하며, 취소·실행 취소·규칙 일시 중지·복원도 지원합니다. 팝업과 관리 화면에서 숨김과 이동을 구분합니다. 이동은 화면에서 치우는 기능이므로 원래 자리의 빈 공간과 광고의 로딩·통신이 남을 수 있습니다. 다른 요청 차단이나 공개 숨김 필터를 해제하지는 않으며, 광고 차단 감지 회피를 보장하지 않습니다.

스포츠서울 홈의 양옆 고정형 쇼핑·게임 배너는 **화면 밖으로 이동**시킵니다. 0.3.1의 `display:none` 방식 대신 외곽의 CSS `translate`만 바꾸어 프레임의 노드·표시 상태·160×600 크기를 유지합니다. `sportsseoul.com`과 `www.sportsseoul.com`에서 관측한 고정 배치 외곽·빈 주소 iframe·크기·완료 상태를 함께 판별하므로, 광고 요소의 ID와 클래스가 바뀌어도 적용됩니다. 일반 텍스트·기사·링크·동영상 등 추가 콘텐츠가 있는 영역은 보존하고, 사이트 차단을 끄면 이동하기 전 위치로 복원합니다.

2026-10-05 실제 탭에서 이 구조의 광고 프레임 4개를 확인했습니다. 광고는 `html-load.com`으로 전달되고 차단 시 `content-loader.com`으로 전환했습니다. 페이지 원본에는 대체 서버가 모두 실패하면 스타일을 제거하는 코드도 있어 해당 도메인의 전체 차단은 추가하지 않았습니다. 이후 사용자 환경에서 `Too many inventory failures`라는 광고 허용 안내가 나타나 이동 방식으로 변경했습니다. 이는 광고 통신을 허용한 채 화면에서 치우는 방법이며, 다운로드·추적 요청은 남습니다. 광고 제공자가 화면 내 위치까지 검사하거나 다른 필터가 광고 요청을 차단하면 안내가 다시 나타날 수 있습니다. 감지 회피 성공을 보장하지 않습니다.

현재 확인한 PC 홈과 같은 구조의 고정 배너가 대상입니다. `news/read/1639264` 기사에서도 적용을 확인했지만, 다른 레이아웃·크기의 광고는 별도 확인이 필요합니다. 동일 광고에 사용자가 저장한 수동 숨김 규칙은 명시적 선택을 존중해 기존 `display:none` 동작을 유지합니다. 이런 규칙이나 공개 필터로 이미 숨겨진 광고를 이동 기능이 강제로 표시하지는 않습니다. 이미 광고 허용 안내로 교체된 문서는 확장 업데이트 후 페이지를 다시 불러와야 합니다.

**규칙 관리 · 백업 → 공개 광고 필터**에서 공개 필터의 실제 활성 상태, 목록 버전과 변환된 규칙 수를 확인할 수 있습니다. 공개 필터만 끄면 기존의 기본 배너 차단과 우클릭 숨김은 계속 사용할 수 있습니다. 정상 콘텐츠가 사라지면 이 스위치 또는 현재 사이트 차단을 끄고 새로고침해 확인합니다.

현재 포함된 공개 묶음은 네트워크 규칙 **52,337개**(차단 51,738개·허용 599개)와 CSS 숨김 규칙 **25,017개**입니다. 전체 목록에 포함된 규칙 수이며 페이지에서 차단한 광고 수와 다릅니다. 버전은 `202610041909-44a36f0d2907`입니다.

폭이 좁은 광고 iframe 안에 **이 광고 숨기기** 패널이 갇히던 문제를 수정했습니다. 이제 선택 테두리는 원래 광고 위치에 두고, 상위·하위 영역, 미리보기, 저장·취소와 실행 취소는 최상위 페이지에서 표시합니다. 규칙은 실제 선택한 프레임의 출처에 저장됩니다. 광고 프레임이 이동·교체되어 연결이 끊기면 선택 도구를 닫으며, 새로 들어온 광고에 이전 조작을 적용하지 않습니다. 새로운 권한은 추가하지 않았습니다.

팝업의 **규칙 관리 · 백업**에서 모든 사이트의 수동 규칙을 검색하고 개별 일시 중지·재개·삭제할 수 있습니다. 광고 서버 도메인에 대한 요청 차단 규칙과 로컬 JSON 백업·가져오기도 추가했습니다. 아래의 적용 범위와 가져오기 동작을 확인하세요.

디시인사이드 PC 갤러리의 **파워링크 광고 행·댓글돌이 행**을 자동으로 숨깁니다. 광고의 사진·문구·삽입 위치나 중복된 ID 대신 사이트의 전용 광고 행 구조를 기준으로 적용하므로, 댓글을 다시 불러오거나 광고 내용이 바뀌어도 숨김을 유지합니다. 광고 표시가 있는 하단 파워링크 영역도 처리합니다. 규칙은 `gall.dcinside.com`에만 적용하며, 일반 댓글에 ‘파워링크’나 ‘댓글돌이’라는 단어가 들어 있다는 이유로 숨기지는 않습니다.

네이버 홈에서 관측한 배너 요청 주소와 광고 영역을 추가했습니다. 광고가 사용하는 `about:blank` / `srcdoc` 프레임에서도 메뉴를 표시하고, HTTP/HTTPS 출처가 확인되는 프레임에서는 선택 도구를 실행합니다. 메뉴 등록은 네트워크 필터 초기화와 독립적으로 복구합니다.

## 남아 있는 광고 숨기기·이동시키기

1. 광고의 이미지나 문구를 **우클릭 → 이 요소 숨기기…**로 선택합니다.
2. 파란 테두리가 숨길 영역을 표시합니다. **상위 영역 / 하위 영역**으로 조정하거나 다른 요소를 눌러 바꿉니다.
3. **숨김 미리보기**로 결과를 확인합니다. **취소 (Esc)**는 저장하지 않고 원래 화면으로 돌립니다.
4. **저장**을 누르면 지금 페이지에서 숨기고, 다음 방문이나 같은 요소의 재삽입 때에도 적용합니다.
5. 직후 표시되는 **실행 취소**, 또는 확장 팝업의 **숨김·이동 규칙 → 복원**으로 되돌립니다. **모두 복원**은 현재 사이트의 수동 규칙만 지웁니다.

요소를 화면 밖으로 옮기려면 첫 단계에서 **이 요소 이동시키기…**를 선택하고 **이동 미리보기**로 확인합니다. 같은 사이트·프레임·선택자의 기존 규칙을 다른 방식으로 저장하면 해당 규칙을 갱신합니다. 저장 직후 **실행 취소**는 이전 규칙으로 되돌리며, 그동안 해당 규칙이 바뀌었다면 최근 변경을 덮어쓰지 않습니다. 이미 이동한 요소는 화면에서 우클릭할 수 없으므로 팝업이나 규칙 관리에서 일시 중지·복원한 뒤 다시 선택합니다. 인라인 문구는 이동 가능한 상자로 바뀌면서 줄바꿈이 달라질 수 있으므로 미리보기로 확인합니다. 이동이 실제로 적용되지 않는 영역은 저장하지 않고 다른 영역 선택을 안내합니다.

사이트 자체 메뉴 때문에 우클릭 메뉴를 사용할 수 없다면, 확장 팝업의 **요소 숨기기** 또는 **요소 이동시키기**를 누르고 페이지에서 광고를 클릭합니다. 이후 같은 미리보기·저장 절차를 사용합니다.

내용이 자주 바뀌는 광고는 사진이나 제목만 선택하기보다 **상위 영역**으로 광고 한 줄 또는 카드 전체를 선택하면 더 안정적으로 숨길 수 있습니다. 다만 순서에만 의존하는 수동 규칙은 댓글 추가·재정렬에 영향을 받을 수 있어, 확인된 반복 광고는 이번 디시인사이드 규칙처럼 전용 광고 컨테이너를 기준으로 처리합니다.

팝업의 **기본 규칙으로 숨김**은 현재 최상위 문서에서 기존 기본 규칙으로 가린 요소 수입니다. 공개 CSS 필터·프레임 내부 요소·네트워크 차단 요청 수는 포함하지 않습니다. **공개 숨김 필터**에는 현재 문서에 적용 가능한 규칙 수를 표시하며, 숨긴 광고 수가 아닙니다. **숨김·이동 규칙**은 우클릭/직접 선택으로 저장한 규칙 수이므로, 자동 차단이 작동해도 0일 수 있습니다. 페이지 연결이 없으면 0으로 표시하지 않고 **확인 불가 / 페이지 새로고침 필요**를 안내합니다. **상태 다시 확인**으로 필터·페이지 연결·메뉴 상태를 다시 읽을 수 있습니다.

우클릭 숨김은 페이지의 요소를 가리는 기능입니다. 선택한 요소의 이미지·스크립트 요청까지 새로 차단하는 기능은 아닙니다. 네트워크 차단은 별도의 기본 필터와 사용자가 추가한 광고 서버 규칙이 처리합니다.

## 규칙 관리와 백업

팝업에서 **규칙 관리 · 백업**을 누르거나, Chrome 확장 관리 화면에서 **확장 프로그램 옵션**을 엽니다.

- **수동 숨김·이동 규칙:** 사이트·이름·선택자로 검색하고, 개별 규칙을 삭제하지 않고 일시 중지했다가 다시 켤 수 있습니다. 기존 팝업의 **복원**은 규칙 삭제입니다.
- **광고 서버 규칙:** `ads.example.com`처럼 광고 서버의 도메인만 입력합니다. URL·경로·와일드카드는 받지 않습니다. 해당 도메인과 하위 도메인으로 가는 제3자 이미지·스크립트·프레임·데이터 요청 등을 차단합니다. 페이지 탐색(`main_frame`)과 영상 파일(`media`) 요청은 제외합니다. 광고 전용 서버가 아닌 공용 서버를 지정하면 정상 기능에도 영향을 줄 수 있습니다.
- **요청을 시작한 사이트:** 지정하면 그 호스트와 하위 도메인에서 시작된 요청에만 적용됩니다. 빈칸이면 모든 사이트에 적용됩니다. 페이지 안의 다른 회사 iframe에서 발생한 요청은 iframe 출처를 기준으로 하므로 최상위 사이트 범위와 같지 않습니다. 네트워크 규칙·사이트 예외 변경 후 페이지를 새로고침합니다.
- **내보내기:** 수동 숨김·이동 규칙·사용자 광고 서버 규칙·차단을 중지한 사이트 목록을 JSON 파일로 저장합니다. 파일에는 사이트 이름·선택자·규칙 설명과 숨김/이동 방식이 포함됩니다. 새 백업은 버전 2 형식이며 이전 확장에서는 가져올 수 없습니다. 기존 버전 1 백업은 계속 가져올 수 있고 숨김 규칙으로 적용합니다.
- **가져오기:** 이 확장의 백업 JSON을 선택하면 추가·중복 건수를 먼저 표시합니다. 적용 버튼을 눌러야 저장되며, 기존 규칙에 합칩니다. 중복 규칙은 기존 설정을 유지하고 전체 차단 켜짐/꺼짐 상태도 유지합니다. 백업에 들어 있는 사이트 예외는 추가됩니다. 잘못된 형식이나 한도 초과 파일은 전체를 거절하며 일부만 저장하지 않습니다.

수동 숨김 규칙과 광고 서버 규칙은 각각 최대 1,000개, 사이트 예외는 최대 500개입니다. 가져올 파일은 최대 8 MiB입니다. EasyList/uBlock/AdGuard 필터 문법이나 다른 제품의 백업 파일을 그대로 가져오는 기능은 아직 없습니다. 파일은 로컬에서만 읽고 서버에 업로드하지 않습니다.

## 차단 범위와 설정

- **전체 차단**과 **현재 사이트 차단**을 각각 켜고 끌 수 있습니다. 자동 숨김과 수동 숨김도 함께 일시 중지되며, 규칙은 삭제되지 않습니다.
- 사이트 예외는 해당 호스트와 하위 도메인에 적용됩니다. 상위 호스트를 중지한 뒤 하위 호스트에서 다시 켜면, 상위 호스트의 중지 설정도 해제됩니다.
- 네트워크 차단 설정을 바꾼 뒤에는 웹페이지를 **새로고침**합니다. 특히 iframe 요청은 다음 페이지 탐색부터 사이트 예외를 따릅니다.
- 수동 규칙은 **최상위 페이지 호스트 + 대상 프레임 호스트** 조합에 저장됩니다. 다른 최상위 사이트로 전파되지 않으며, 같은 호스트의 다른 경로·포트에는 적용될 수 있습니다.
- 일반 HTTP/HTTPS iframe과 출처를 확인할 수 있는 `about:blank` / `srcdoc` iframe 내부 요소도 선택할 수 있습니다. 출처가 불투명한 sandbox 프레임, 닫힌 Shadow DOM 내부, Chrome 내부 페이지·웹 스토어 등은 지원 범위에 제한이 있습니다.
- 프레임 안에서 선택해도 조작 패널은 최상위 페이지에 표시됩니다. 최상위 페이지에 확장이 연결되지 않았다면 페이지를 새로고침한 뒤 다시 선택합니다. 프레임 안의 **상위 영역**은 해당 문서 안에서 확장되며, iframe 상자 전체를 선택하려면 팝업의 **요소 숨기기**을 사용합니다.
- 전체 페이지, 주요 본문 컨테이너, 동영상·오디오 요소와 그 컨테이너는 선택하지 못하도록 보호합니다. 우클릭한 대상이 없거나 지원하지 않는 화면이면 확장 아이콘에 `!`가 표시되며, 아이콘에 마우스를 올리면 이유를 확인할 수 있습니다.

## 공개 필터와 기본 필터의 범위

공개 목록은 [EasyList](https://easylist.to/)와 [FilteringDev/filterslists-KO의 AdGuard Classic](https://github.com/FilteringDev/filterslists-KO)입니다. 원본을 빌드 도구에서 읽어 하나의 정적 네트워크 규칙 묶음과 도메인별 CSS 데이터로 변환합니다. 이미 변환한 파일을 포함하므로 설치할 때 별도 빌드가 필요하지 않습니다. 출처·다운로드 시각·SHA-256·변환 통계·제외 사유는 `filters/`에 기록합니다.

- **광고 요청:** AdGuard DNR 변환기로 지원되는 차단·허용 규칙과 예외를 변환합니다. 공개 목록의 허용 예외는 기존 기본 요청 차단보다 우선합니다. 사용자가 직접 추가한 도메인 규칙은 공개 목록보다 우선하고, 전체/사이트 일시 중지는 모두보다 우선합니다.
- **광고 영역:** 표준 CSS 숨김, 도메인별 규칙·제외 도메인·숨김 예외를 적용합니다. 광고가 나중에 삽입되어도 브라우저 CSS가 처리하므로 공개 선택자 수천 개로 매번 전체 문서를 다시 검색하지 않습니다. 본문 루트와 영상·오디오 요소 및 그 컨테이너를 보호합니다.
- **지원 범위:** 공개 목록 전체와 uBlock Origin/AdGuard 엔진을 그대로 구현한 것은 아닙니다. 스크립틀릿, 절차적/확장 CSS, 임의 스타일 실행 등은 포함하지 않습니다. URL 조건을 그대로 표현할 수 없는 일부 숨김 예외는 도메인 단위로 더 넓게 허용해 정상 콘텐츠를 보호합니다. 이 경우 광고가 남을 수 있습니다.
- **업데이트:** 이 버전은 로컬에서 목록을 갱신·변환한 뒤 확장을 다시 로드하는 방식입니다. 브라우저 안의 자동 목록 다운로드나 원격 코드 실행은 없습니다. 새 묶음의 검증이 실패하면 기존 파일을 유지합니다. 브라우저의 정적 규칙 한도로 공개 묶음을 활성화하지 못하면 관리 화면에 오류를 표시하고 기본 차단·우클릭 기능을 유지합니다.

`rules/banner-ads.json`에는 24개 광고 호스트에 대한 제3자 요청 규칙과, 실제 네이버 홈에서 확인한 배너 관련 경로 규칙 8개가 들어 있습니다. 네이버 경로 규칙은 `www.naver.com`에서 시작된 특정 배너 스크립트·광고 데이터·광고 표시가 확인된 프레임 요청에만 적용하므로, 같은 사이트에서 제공하는 배너도 차단합니다. 일반 검색·쇼핑 콘텐츠나 `pstatic.net` 전체를 차단하지 않습니다. 최상위 문서와 `media` 유형 요청은 제외합니다. 플레이어 내부 동작, 광고 건너뛰기, 광고 차단 감지 우회는 구현하지 않습니다.

사이트마다 광고 제공 방식이 달라 모든 광고를 제거하지는 못합니다. 남는 배너는 수동 숨김이나 사용자 광고 서버 규칙으로 보완합니다. 사이트가 광고와 정상 기능에 같은 스크립트를 사용하면 공개 필터 또는 사이트 차단을 잠시 끄고 새로고침해 복구할 수 있습니다. 일반 배너 차단이 영상 서비스에도 간접 영향을 줄 수 있으므로 동영상 재생을 보장하는 의미는 아닙니다.

수동 선택자는 현재 페이지에서 하나의 요소에 맞도록 생성합니다. 사이트 개편 후 선택자가 여러 요소에 맞으면 자동 적용하지 않습니다. 위치 기반 규칙은 페이지 구조 변경 후 재선택이 필요할 수 있습니다. 페이지 변화에 맞춰 다시 적용하지만 광고가 잠깐 보이는 현상까지 보장하지는 않습니다.

페이지가 바뀔 때 이미 숨긴 요소를 매번 다시 표시하고 숨기는 처리를 줄였습니다. 숨긴 요소와 관련된 속성·내용·조상 요소·스타일시트 변경에는 안전 검사를 다시 수행합니다. 외부 DOM 변경 뒤 선택자 검색 자체는 문서 전체를 대상으로 하므로, 이 변경이 모든 사이트에서의 속도 우위를 의미하지는 않습니다.

### 공개 목록을 직접 갱신할 때

일반 사용에는 아래 작업이 필요하지 않습니다. 목록을 새로 받을 때만 Node.js 22 이상과 pnpm을 사용합니다. 프로젝트 최상위 폴더에서 실행합니다.

```powershell
pnpm --dir adblocker/tools/filter-builder install --frozen-lockfile --ignore-scripts
node adblocker/tools/filter-builder/build.mjs
```

완료 후 확장과 웹페이지를 새로고침합니다. 저장해 둔 원본으로 다시 만들려면 `--offline`, 직전의 완전한 묶음으로 되돌리려면 `--rollback`을 붙입니다. 다운로드·예외 변환·한도 검증 실패 시 새 묶음을 적용하지 않습니다. 파일 교체 도중 중단되었다면 다시 실행하여 이전 묶음을 복구한 뒤 진행합니다. 잠금 파일 안내가 나오면 표시된 빌드 프로세스가 종료되었는지 확인한 뒤 안내된 `.build.lock` 파일만 지우고 재실행합니다. 빌드가 끝나기 전에는 확장을 다시 로드하지 않습니다. 최초 빌드에는 되돌릴 이전 묶음이 없을 수 있습니다. 자세한 출처와 범위는 [필터 문서](filters/README.md)에 기록합니다.

## 저장 데이터와 권한

- `storage`: 전체 설정, 사이트 예외, 수동 선택자·짧은 요소 설명·사용자 광고 서버 도메인·저장 시각을 `chrome.storage.local`에 저장합니다.
- `contextMenus`: 우클릭 메뉴를 추가합니다.
- `declarativeNetRequest`: Chrome의 선언적 네트워크 필터를 적용합니다.
- `sidePanel`: 팝업과 같은 제어 화면을 Chrome 사이드바에서 엽니다.
- `scripting`: 선택형 지문·GPC·광고 API 보호 스크립트를 문서 시작 시 등록하고 사이트 예외·설정 해제에 맞춰 갱신합니다.
- HTTP/HTTPS 사이트 접근: 배너와 사용자가 선택한 요소를 찾아 숨깁니다.

이 확장이 분석 서버로 데이터를 보내거나 외부 코드를 다운로드하는 기능은 없습니다. 규칙은 이 브라우저 프로필의 로컬 저장소에 보관하며 자동 동기화하지 않습니다. 사용자가 직접 내보낸 백업은 선택한 다운로드 위치에 별도 보관됩니다. Chrome에서 확장을 제거하면 해당 확장의 로컬 설정과 규칙은 삭제됩니다.

## 개발 검증

Node.js 20 이상에서 프로젝트 최상위 폴더 기준으로 실행합니다. 패키지 설치 없이 기본 테스트가 실행됩니다.

```powershell
node --test adblocker/tests/*.test.mjs
node adblocker/fixtures/server.mjs
```

브라우저 테스트는 선택 사항입니다. Playwright가 있는 환경에서는 아래처럼 모듈 경로를 지정합니다.

```powershell
$env:PLAYWRIGHT_MODULE = 'C:\path\to\playwright\index.mjs'
node --test adblocker/tests/picker.browser.test.mjs
node adblocker/tests/browser-smoke.mjs $env:PLAYWRIGHT_MODULE 'C:\path\to\extension-capable-browser.exe'
```

첫 번째 브라우저 테스트는 설치된 Chrome에서 실제 DOM과 요소 선택 UI를 검사하며 Chrome 메시지 API는 모의 구현입니다. 두 번째는 실행 중인 로컬 fixture와 확장 프로그램을 실제로 로드해 검사합니다. 일반 배포 Chrome은 자동화의 `--load-extension` 인수를 제한할 수 있으므로, 전체 확장 자동화에는 Edge 또는 Chrome for Testing처럼 해당 인수를 지원하는 실행 파일을 사용합니다. 일반 Chrome의 수동 설치는 위 설치 절차를 따릅니다.

2026-10-05, **0.4.0 검증: 확장 테스트 106개 모두 통과·실패 0개·생략 0개**입니다. 브라우저 간 자원 경합을 줄이도록 `--test-concurrency=2`로 실행했습니다. 수동 이동의 메뉴·프레임 간 연결, 미리보기·취소·저장·실행 취소, 인라인 요소 처리, 새로고침·재삽입 후 적용과 스타일 복원을 검사했습니다. 실제 확장을 로드한 Edge에서는 이동 규칙의 백업·가져오기·일시 중지·삭제, 프레임 문서 동일성과 크기 보존도 통과했습니다. 스포츠서울 테스트 10개와 공개 필터·네트워크·기존 숨기기 검사도 함께 통과했습니다. 로그는 `test-results/latest-test-run.txt`, 확인 화면은 `test-results/move-picker.png`와 `test-results/move-popup.png`입니다. 0.4.0의 실제 사용자 Chrome 탭 적용은 확장·웹페이지 새로고침 후 확인해야 합니다.

사용자가 Chrome에서 0.3.2로 업데이트한 후 정상 표시를 확인했습니다. 실제 탭 검사에서도 광고 프레임 4개가 `display:block`·160×600 크기를 유지한 채 화면 밖 좌표에 있었고, 기사 제목 링크 185개와 정상 레이아웃이 남았습니다. 오류 안내 iframe은 없었습니다. 확인 화면은 `test-results/sportsseoul-offscreen-0.3.2.jpg`입니다. 이는 확인 당시 결과이며, 장기적인 광고 서버 변경까지 보장하지 않습니다.

공개 `html-load.com/loader.min.js`를 실행하지 않고 정적으로 분석했습니다. 일반 탐지 분기는 `display:none`·`visibility:hidden`·크기 0을 검사하며 탐지 요소 자체도 화면 밖에 놓습니다. 그러나 이번 `Too many inventory failures` 판정은 해당 메인 로더에서 찾지 못했으므로, 이 근거만으로 이동 방식의 감지 회피를 확정하지 않습니다.

0.3.0에서 검증한 변환 도구 테스트 13개와 공개 필터 생성물은 이번에 변경하지 않았습니다. 기존 검증은 두 목록의 차단·허용 예외, 정규식 162개 지원, 공개 필터·전체·사이트 스위치, CSP 환경, 수동 규칙 보존, 본문·영상·조작 패널 보호를 포함합니다. 빌드 검사는 목록 간 취소 규칙·혼합 예외·할당량·실패 복원·동시 빌드 차단과 오프라인 체크섬 재현을 포함합니다. 변환 도구 로그는 `test-results/filter-builder-test-run.txt`입니다.

기존 좁은 iframe 조작 회귀도 통과했습니다. 미리보기·영역 변경 응답을 기다리는 동안 누른 Esc는 응답 직후 취소하도록 보완했으며, 저장 중 Esc는 저장 취소로 처리하지 않습니다. Edge에서 폭 160px 프레임의 버튼이 최상위 페이지의 352px 패널로 표시되는지, 중첩 프레임·srcdoc의 선택·미리보기·저장·복원, 상위·하위 영역 조절, 새 선택 도구를 유지한 채 이전 규칙 실행 취소, 원본 문서 교체·삭제 시 선택 해제를 검증했습니다. 스크린샷은 `test-results/frame-picker-fixed.png`, `test-results/public-filter-options.png`입니다.

Chrome DOM 테스트에는 네이버·디시 광고 구조와 일반 콘텐츠 보존, 페이지 변경 뒤 재적용이 포함됩니다. Edge에서는 내장 Naver DNR 회귀, 사용자 도메인·하위 도메인·요청 출처별 차단, 미디어·최상위 문서·동일 사이트 요청 제외, 규칙 일시 중지, 실제 백업 다운로드·미리보기·재가져오기, 팝업에서 관리 화면 열기도 확인했습니다. 외부 광고 서버로 요청하지 않고 로컬 모형과 브라우저의 규칙 판정 API를 사용합니다. 성능 검사는 무관한 DOM 변경 뒤 이미 숨긴 배너의 스타일 쓰기·크기 재측정이 발생하지 않는지 확인하는 범위이며, 경쟁 제품과의 속도 비교는 아닙니다.

이전 0.1.2에서는 Edge 154로 실제 네이버 홈·디시 게시글의 광고 제거와 정상 콘텐츠 보존을 확인했습니다. 일반 Chrome의 수동 확장 로드와 실제 사이트별 호환성은 업데이트 후 사용자 환경에서도 확인해야 합니다.

## 0.6.0 선택형 추적 차단 변경 기록

**규칙 관리 · 백업 → 추적 차단 강화**에서 두 설정을 독립적으로 켤 수 있습니다. 기존 동작을 유지하도록 둘 다 기본값은 꺼짐입니다.

- 분석·추적 차단: Google Analytics(gtag), Hotjar, Yandex Metrica의 스크립트·수집 요청. Google Tag Manager의 일반 `/gtm.js` 컨테이너는 이 기능에서 차단하지 않습니다.
- 오류 수집 차단: Sentry와 Bugsnag의 스크립트·수집 요청. 사이트의 오류 진단 전송도 차단됩니다.

직접 검토한 서비스 규칙 6개+4개이며 EasyPrivacy 전체 목록을 추가한 것은 아닙니다. 테스트 사이트에만 적용되는 새 규칙이나 점수 조작은 없습니다. 공개 필터와 독립적이며 전체·사이트 일시 중지가 우선합니다. 변경 후 페이지를 새로고침하세요. 설정은 로컬에 저장되며, 규칙 백업 JSON에는 이 스위치들이 포함되지 않습니다.

2026-10-06 격리 Chrome에서 Adblock-tester는 기존 광고 차단 75점, 분석·추적 차단 추가 90점(2회), 오류 수집 차단까지 추가 100점(2회)이었습니다. 점수는 해당 사이트의 11개 서비스·22개 검사 결과이며 모든 광고나 추적 요청의 차단율이 아닙니다. 기존 공개 목록에는 테스트 배너 경로 전용 규칙도 있어 일반 배너 탐지 능력과 구분해야 합니다.

스포츠서울 홈·기사의 본문과 이미지 표시를 확인했습니다. 기존 광고 이동 구현은 유지했으며 광고 로더 전체 허용 예외를 추가하지 않았습니다. 이번 접속에는 과거의 고정 160×600 광고가 없어 해당 광고의 실제 사이트 이동 재검증은 미수행입니다. 구조가 바뀌는 광고의 이동·새로고침 유지 동작은 로컬 재현 테스트로 확인했습니다. 화면 밖 이동은 광고 통신 자체를 막지 않습니다.
